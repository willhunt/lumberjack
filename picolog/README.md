# picolog

Safe wrappers over the Pico Technology data logger drivers.

Currently the ADC-20 / ADC-24 high resolution loggers (`picohrdl`).

## How the bindings work

The drivers are C libraries. `src/raw/` holds bindings generated by bindgen and
**committed to the repository**, rather than generated during the build.

That matters: bindgen needs libclang and the PicoSDK headers. Running it from
`build.rs` would put both on the critical path of every build on every machine
forever. Committing the output means only whoever regenerates them needs the
toolchain, and this crate builds anywhere.

The bindings use bindgen's `--dynamic-loading`, so the driver is looked up at
runtime with `libloading` instead of being linked. A machine with no Pico
software installed still builds and runs; the failure appears when a unit is
opened, and says what it looked for.

## Regenerating

Only needed if Pico change a header. Requires LLVM and PicoSDK installed.

```powershell
bindgen "C:/Program Files/Pico Technology/SDK/inc/HRDL.h" `
  --dynamic-loading PicoHrdl `
  --allowlist-function "HRDL.*" `
  --allowlist-type "(HRDL|enHRDL|enSettings|enBlock).*" `
  --allowlist-var "(HRDL|INVALID).*" `
  --no-layout-tests `
  -o src/raw/hrdl.rs
```

Then put back the two `//!` lines and the `#![allow(...)]` at the top of the
file, which bindgen writes with `--raw-line` but mangles.

## Checking a unit

```
cargo run --example probe -- [channel]
```

Loads the driver, opens a unit, prints what it is, enables one channel and takes
five timed readings. The smallest thing that exercises the whole path, so if it
works the bindings are sound.

## Where the driver is looked for

1. `picohrdl.dll` — beside the executable, or on PATH. How a packaged install
   should ship it.
2. `C:\Program Files\Pico Technology\SDK\lib\picohrdl.dll` — where PicoSDK puts
   it on a development machine, which nothing points at by default.

## Notes

- x86_64 only in practice. The header declares `__stdcall`, which 64-bit Windows
  ignores because it has one calling convention, so bindgen's `extern "C"` is
  correct there. On a 32-bit target it would not be, and would corrupt the stack.
- `HRDLGetSingleValue` blocks other driver calls, so a unit belongs to one thread.
- A conversion takes 60 to 660 ms **per channel**, so eight channels at the
  fastest setting is roughly half a second for a full scan.
